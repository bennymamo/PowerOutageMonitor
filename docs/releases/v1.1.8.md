# Flockle Grid Outage Monitor 1.1.8

Build 21, 28 September 2026. Install over the existing permanent-signature release to preserve settings and History; do not uninstall first.

## Changes

- Improve short confirmation wake-ups with granted exact-alarm access and bounded CPU protection. Bound local charger-loss verification to one minute plus the configured confirmation delay; preserve a bounded first-check grace after provider restart.
- Keep qualified completed EcoFlow readings valid through their original evidence expiry, fixing misleading UNKNOWN dashboard/status readings between checks. Do not refresh receipt timestamps or invert grid codes: 0 remains connected, 1 remains off-grid.
- Use explicit outage-decision provenance instead of interpreting English message text. Show evidence age/origin, qualification and changing-report counts; distinguish current and retained readings.
- Show aggregate EcoFlow home-battery percentage, receipt age and origin when reported, separately from phone battery. Reject retained, old, invalid and individual-pack values as aggregate replacements. Percentage alone is not an available-energy/runtime estimate.
- Send one ordered, deduplicated GRID CONNECTION CONFIRMED follow-up after a meter-based restoration when new qualified code-0 evidence arrives. Meter-based restoration still does not wait for inverter reconnection.
- Add `/ecoflow_hourly` to temporarily use hourly checks after confirmed grid reconnection while a manually restarted UPS leaves the phone charger off. `/ecoflow_auto` restores automatic scheduling. Charger return or verified new grid loss cancels the override; failures/pending outages remain on the rapid schedule. Hourly mode can delay detection of another outage by up to an hour and refuses activation during unknown/reconnecting grid state.
- Add `/restart_monitoring` to recreate the selected provider inside the foreground service without clearing settings, History, incident state or queued alerts. It cannot recover an unreachable Telegram receiver remotely.
- Bound EcoFlow check duration, abort active network operations, make MQTT waits cancelable, renew sessions after repeated broker failures even while the charger is off, cap disconnected-charger failure backoff at five minutes and retry on phone-network recovery.
- Keep delayed read-only `/status` and `/help` requests valid for 24 hours with a late-receipt notice. Mutating commands retain their five-minute limit and sender/replay protections. Retry Telegram replies without re-executing controls and preserve sanitized command receipt/reply diagnostics.
- Replace “Next check: after this check” with stage, elapsed time and deadline/overdue information. Show concise meter values, phone-network validation and temporary schedule state.

## Validation and limits

- 297 local unit tests passed with zero failures/errors/skips.
- Android lint completed with zero errors (146 warnings and 8 hints).
- The complete 30-test Android instrumentation suite passed on Android 6/API 23 and Android 16/API 36. No instrumentation was run on the Samsung.
- The signed release candidate passed permanent-signature verification. Publication and installation use a final signed build from the release commit, reverified before distribution.

The preceding real outage proved the installed 1.1.7 sampled-code-1/zero-meter corroboration and nonzero-meter restoration paths, but not these new changes. A later controlled physical test remains necessary for actual latency, home-battery values, reconnect follow-up, remote commands and alarm behavior. Android idle/network limits and manufacturer process kills can still delay monitoring. Uncertain remote send acknowledgements can still cause a duplicate despite local deduplication/reply retry safeguards.
